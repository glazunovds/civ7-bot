# Expansion Planner: mod internals

See the root `CLAUDE.md` first (commands, game loop, gotchas). The mod is `mod/expansion-planner/`; paths below are relative to it, and everything is in `ui/`. This file sits outside the mod folder so it does not ship with the mod. Every file is named `xpl-*`: the game resolves imports by file name across mods.

## Loading
- **`expansion-planner.modinfo`:**
  - Shell group: `config/input.xml` (F8 action `open-expansion-planner`) and text.
  - Game group: text, `<ImportFiles>` (generated: `python -I tools/sync-modinfo.py`) and the single UIScript `ui/xpl-main.js`.
  - Group `xpl-game-dmt` (criteria `ModInUse detailed-map-tacks`): `ui/integrations/xpl-dmt-present.js`.
- **`ui/xpl-main.js`** imports everything else, so each stateful module has exactly one instance. It boots settings and the DMT bridge, and registers the panel, the dock button, the hotkey, the production-menu pills (`hud/xpl-production-tacks.js`), the recalculation watcher (`hud/xpl-recalc-watch.js`) and the growth hints (`hud/xpl-growth-advisor.js`). The food lens registers itself when the Empire tab module is imported (`map/xpl-food-lens.js`).
- **Text:** `text/en_us/InGameText.xml` (`<EnglishText><Row Tag>`), `text/ru_ru/InGameText.xml` (`<LocalizedText><Replace Tag Language="ru_RU">`), `text/en_us/ModInfoText.xml` (name and description, both languages). The `.html` template uses LOC keys in `data-l10n-id` / `data-tooltip-content`; the panel composes tooltips once in `onInitialize`.

## Layers
| Folder | Role | Rule |
|---|---|---|
| `core/` | Pure logic: hex grid, yields, profiles, tuning, rule book, scorers, placement model and solver, advisors | No engine globals. Node-tested with real game data |
| `data/` | Engine adapters: read the map, players and engine numbers; run jobs; write results to state | Wrap engine calls in `safe()`; engine-only code lives here |
| `services/` | `xpl-state` (observable runtime state: results, status, stale, advice), `xpl-settings` (persisted), `xpl-advice` (suggested recalculations), `xpl-scheduler` (generator jobs, 6 ms per frame), `xpl-log` (`[XPL]` via `console.warn`) | State/settings have a recursion guard (8 nested updates) |
| `integrations/` | DMT: status, bridge (read/place/clear tacks, one operation at a time, diff-based replace, `onProgress`), our tack registry (`_XPL_OBJ_TACKS_LIST` in GameTutorial; entries `{x,y,type,src:"settle"\|"build"\|"wonder",pid,turn,role?}`) | We only ever remove our own tacks |
| `map/` | `xpl-overlay` (fills, labels, icons, VFX glows over fog), `xpl-camera`, `xpl-food-lens` (a LensManager lens + layer, button in the mini-map lens menu) | |
| `panel/` | The panel (`xpl-panel.*`) and one class per tab (`xpl-tab-*.js`). Setting `panelLarge` (default on, header button «Меньше»/«Больше») adds `.xpl-frame--large`: 60rem wide, down to the bottom of the screen | Tabs compute only when shown |
| `hud/` | Dock button (decorates `panel-sub-system-dock` via `addButton`), F8 hotkey, production-menu pills (decorates `panel-production-chooser`), recalc watcher | Decorate; never replace base files |

## Tabs: data flow
- **Settlements:**
  1. `data/xpl-site-job.js` (`buildSiteContext`) runs `core/xpl-site-pipeline.js` (candidates, engine claim check last, scoring, selection).
  2. **Scoring:** `core/xpl-site-roles.js` scores each candidate as a future **city** (`core/xpl-site-scorer.js`: radius 3, room, production, adjacency potential) and/or a kept **town** (`core/xpl-town-scorer.js`: food in rings 1–2, food sent to a connected city, best Focus tiles), and keeps the better role (setting `siteRoles`: BOTH/CITY/TOWN).
  3. **Shared tiles:** availability shares come from nearby centres (`TUNING.SHARE`). Tiles owned by others count 0, free tiles on a rival's border 0.5.
  4. **Selection:** `core/xpl-site-selector.js` is a lazy greedy; picks become PLANNED / PLANNED_TOWN centres.
  5. **Tacks:** a site tack's role is stored in our registry.
- **Buildings:** `data/xpl-building-job.js` `startBuildingPlan(target, settings)`.
  1. **Targets:** a settlement, a planned site (city-centre tack), or `allTarget()` = every settlement.
  2. **Members and roles:** region mode adds neighbours. `settlementRole`: city → CITY; town → TOWN unless «Городки как будущие города»; a planned site → its tack's stored role, else the current search pick, else scored on the spot. TOWN members only get `Buildings.Town` types (Altar and warehouses).
  3. **Engine data:** per city, `CityOperations.canStart(BUILD)` (Plots / ExpandUrbanPlots → which tiles are valid now) and `city.Yields.calculateAllBuildingsPlacements()` (exact yields per building and plot).
  4. **Calibration:** gaps between our adjacency and the game's become `PlanState.adjCorrection`. Applied only if ≤ 50% disagree, otherwise we suspect our reading. Warehouses get a settlement-wide `extraValue` from the engine's numbers, or `WAREHOUSE_GUESS`.
  5. **Your tacks:** the player's tacks are fixed. Real or generic building tacks fill a slot; wonder tacks make a wonder tile; improvement tacks keep the tile rural (`tile.reserved`). Our "build" tacks are re-planned, except those whose building is already queued (`keptTacks`).
  6. **Solve:** `core/xpl-placement-solver.js` `solveLayout`:
     - greedy by gain, or gain per build turn when time-aware;
     - local moves and pairwise swaps;
     - a repair pass for buildings left without any tile.
     Warehouses compete in the greedy like any other building.
  7. **Results** go to `state.results.plans`, with rows per settlement, `bestNow` (the game's best tile when it beats ours), an ETA or "after the age" flag, `upkeep` (the game's `city.Constructibles.getMaintenance`, else `Constructible_Maintenances`) and `net` (value per turn after upkeep, by the profile; upkeep does not change *where* a building goes, so the solver ignores it). Tacks via `placePlanTacks` (replaces our previous ones near the plan's centres). The «Обновлять булавки сами» option re-places them after each recalculation.
  8. **Actions** (`data/xpl-city-actions.js`, always from a click): «В очередь» queues a city's next 3 planned buildings at their tiles (BUILD with X, Y appends to the queue); the gold box ranks buyable planned buildings by value per gold (`core/xpl-purchase-advisor.js`: net per turn × turns gained; a town gains the rest of the age) and «Купить» sends PURCHASE at the tile; buildings with `net < 0` are listed, with «Снять отметку» only for a type that loses everywhere.
- **Towns:** `data/xpl-town-job.js` collects facts per town.
  - **Convert advice:** `core/xpl-town-advisor.js` (convert / consider / wait / keep / blocked; production versus the gold cost, age pace).
  - **Focus advice:** `core/xpl-town-focus.js`. «Выбрать» sets a Focus with the game's own CHANGE_GROWTH_MODE command (`applyTownFocus`); only for Focuses offered now and towns at population 7+. It counts the town's farms/pastures/plantations/fishing boats, woodcutters/camps/clay pits/mines/quarries, appealing tiles, quarters, buildings and resource tiles, plus `getConnectedCities()` and the Focus list the game offers now (`CityCommands.canStart(CHANGE_GROWTH_MODE, {Type: PROJECT}).Projects`).
- **Wonders:** `data/xpl-wonder-job.js`, Wonder-Alert-style. Our cities' `canStart` gives tiles and turns; completed wonders come from `player.Constructibles.getWonders()` and `Constructibles.getByComponentID`. Rival sites count only if visible on our map, unless the opt-in "omniscient" mode reads rivals' build queues. `core/xpl-wonder-race.js` labels the race. The tile boost counts neighbours' "+1 per adjacent wonder" rules.
- **Empire:** `data/xpl-empire-job.js` `runEmpireOverview` (reuses `runTownAdvisor` for the recommended Focus and `state.results.plans` for what is left). `foodNetwork()` applies the game's food rule (a town with a Focus that is not a unit project sends `getSentFoodPerCity()` to *each* connected city; `getConnectedCities()` lists towns too). "Strongest in" = the yield where a city is ≥ 15% above the average city. The food lens draws the same network.
- **Growth hints:** `hud/xpl-growth-advisor.js` listens for the window event `interface-mode-changed` with `newMode === "INTERFACEMODE_ACQUIRE_TILE"` (params `{CityID}`), and draws marks only. `data/xpl-growth-job.js` ranks the game's EXPAND plots by the profile (+ a share of the value of buildings the plan needs there; an owned tile where the plan builds counts only until that building's turn) and the specialist tiles by `Workers.GetAllPlacementInfo()` (Next − Current yields, minus the added upkeep), on one scale; `choice` names the overall winner.
- **Food and happiness costs** (`core/xpl-scarcity.js`): a specialist's or a building's food/happiness upkeep is weighted by what the settlement keeps after paying it (`city.Yields.getNetYield`): plenty left → down to ×0.3, nothing left → ×1, would go below zero → ×2. Used by the growth hints, the upkeep warnings (`net`) and the gold advice.
- **Autopilot:** `hud/xpl-autopilot.js` (orchestrator: on the local `PlayerTurnActivated` while `state.autopilot.enabled`, or once with «Сделать сейчас»; steps with 250 ms pauses; a log in `state.autopilot.log`; a green dot on the toolbar button) and `data/xpl-autopilot-steps.js` (one function per decision, each returning log entries `{key, args}` → `LOC_XPL_AP_<key>`). Order: threats first (`threatenedSettlements`: a settlement with 2+ hostile military units within 4 tiles; an independent's units count unless `Game.IndependentPowers.getIndependentRelationship(getIndependentPlayerIDFromUnit(unit), local)` is FRIENDLY, a major's while at war) → befriending (`befriend`; threatening independents first, more Influence into an ongoing befriend under threat with `SUPPORT_DIPLOMATIC_ACTION`; ones the game offers nothing for are approached by a unit, stopping 2 tiles from their settlement) → with `settlers`, the Settlements search by itself when a settler (owned or training) needs sites and they are missing or 5 turns old → unit orders first (`data/xpl-autopilot-units.js` `commandUnits`, each option opt-in: `explore`, `settlers` (site of the role that keeps cities and towns 1:1 first, `neededRole`), `defend`, `merchants`, `roam` (military other than the first unit in each city explores: AUTOMATE_EXPLORE if allowed, else a random revealed tile next to the fog within 6 tiles / 3 turns, never foreign land; fortified ones are woken, hurt ones heal; near a threatened settlement they stay); under threat (`threats` passed with `defend` or `roam`) a soldier away from every threatened settlement walks to a free tile within 2 of one that has fewer of our soldiers within 4 (or walking there: goal `{guard}`, `guardsFor`) than hostile units (`reinforce`, log REINFORCE; garrisons stay); migrants (UNIT_CLASS_POPULATION) with `settlers`: «Переселить» `UNITCOMMAND_RESETTLE` joins the settlement owning the tile, city or town (`GameplayMap.getOwningCityFromXY`), `canStart(id, RESETTLE, {})` → `Plots`, sent `{X, Y}` like the acquire-tile screen, our tile = best of `growthAdvice(...).expand` among those Plots; ## Planner model essentials (`core/xpl-placement-model.js`, `PlanState`)
- **Tiles:** tiles are assigned to settlements; slots come from `Districts.MaxConstructibles` (urban and city centre: 2). Urban growth must touch the settlement's urban tiles or centre (`isConnected(sid)`). The plan allows one of each building per settlement (unless `MultiplePerCity`), and never puts a building on a wonder tile.
- **`tileValue`:**
  - planned items' base yields + `extraValue`;
  - adjacency (timed: a neighbour counts from when it exists), × `adjMult` (specialists);
  - the engine adjacency correction;
  - the unique-quarter bonus.
  Weights are the profile's yield weights.
- **Time-aware:** `wt(t) = max(0.05, (H − t) / H)`, where H = turns left in the age (`ageOutlook()`, 150 in the final age). ETAs come from cost / production; planned sites start late; locked buildings get `LOCK_DELAY`. Items finishing after the age keep 5% weight and are flagged.
- **Future tiles** (not owned yet) count at ×0.85, and time-aware no earlier than turn 10. So a tile usable today wins ties.
- **Terrain rules** mirror the game data and DMT:
  - `ValidTerrains`, `ValidDistricts`, `ValidFeatures`, `RequiredFeatureClasses`;
  - `RiverPlacement` (RIVER = river on the tile; OFF_COAST = coast touching land; ANCHORED = navigable river or coast touching land);
  - `AdjacentRiver` / `AdjacentLake` / `AdjacentTerrain`, `NoRiver`, `NoFeature`.
  - A land building that lists `ValidTerrains` (the Modern Airfield: `TERRAIN_FLAT`) still needs an urbanizable tile: no resource, mountain, natural wonder or impassable feature.
  For owned tiles the engine's yes or no wins. Towns (and towns planned as cities) only get the game's PURCHASE answer, which says nothing about city-only buildings: there our rules are the only guard.
- **Constants:** tuning lives in `core/xpl-tuning.js` (sites, towns) and at the top of `data/xpl-building-job.js` (plan timing, region, warehouses).

## Speed (building plans)
Measured in the log line `buildings timing:` (game queries, setup, seed, greedy, search with rounds, repair, describe, results; work counters). `node tools/bench-plan.mjs` runs the same on a fake map.
- **Memo in `PlanState`:** a tile's view depends only on that tile; its value on it and its neighbours. `touch(idx)` (called by place/undo/lift/restore) drops exactly those; `delta()` puts the before-values back after its undo. Tiles edited any other way need `invalidateAll()`.
- **Solver:** the delta cache is indexed settlement → tile → building and drops only tiles within 2 of a placement (time-aware: also that settlement, whose queue got longer). Local-search rounds after the first revisit only settlements near something the previous round changed.
- **Game queries** (`canStart` per building per city, `calculateAllBuildingsPlacements`) run one city per frame and are cached for the turn (`data/xpl-engine-cache.js`): an entry is valid for the same turn, owned tiles and queue, and no event since among buildings/tiles/queue/purchases/population/specialists/unlocks.
- **Incremental recalculation** (`buildings.incremental`, on): the same target with the same `inputSignature` (settings, members and roles, selected and locked buildings, age/civ/unique quarters) within 10 turns re-solves only settlements whose `settlementSignature` (tiles, districts, buildings, tacks, owned tiles) or `engineFingerprint` (what the game said about that city) changed. The others are seeded from `plans.seed` in their old build order.
- **CPU per frame:** 6 ms by default; the Buildings tab asks for 12 ms while the panel is open (`runJob` takes a budget function, read every frame).
- **Rules:** `data/xpl-rules-loader.js` `getRules()` rebuilds the rule book (about 10 ms) when the age, civ, turn or unlocked unique quarters change. Plans store `uniqueQuartersSig`; `hud/xpl-recalc-watch.js` suggests «Пересчитать» (reason UNIQUES) when it no longer matches.

## Engine API cheat sheet (verified in game 1.5.0.44)
- **Map:** `GameplayMap.getYields(idx, pid)` → `[[yieldHash, amount]]`; `getRevealedState`, `getOwner`, `getOwningCityFromXY` (ComponentID), `isRiver`, `isNavigableRiver`, `isWater`, `isMountain`, `isImpassable`, `getAppeal`, `getContinentType`, `isCityWithinMinimumDistance`.
- **Structures:** `Districts.getAtLocation({x,y})` and `MapConstructibles.getHiddenFilteredConstructibles(x, y)` → ids; `Constructibles.getByComponentID(id)` → `{type, complete, location}`.
- **Cities:**
  - `Players.get(id).Cities.getCities()`; `city.isTown`, `population`, `getPurchasedPlots()`, `getConnectedCities()`, `getSentFoodPerCity()`;
  - `Yields.getNetYield(YieldTypes.X)`, `Yields.calculateAllBuildingsPlacements()`;
  - `Production.getConstructibleProductionCost(type)`, `Gold.getBuildingPurchaseCost(YIELD_GOLD, type)`, `Gold.getTownUpgradeCost()`;
  - `BuildQueue.getQueue() / getTurnsLeft(type) / getPercentComplete / currentProductionTypeHash / currentTurnsLeft`;
  - `Growth.growthType / projectType`; `Constructibles.isAdjacencyUnlocked(id)`.
- **Operations and commands:**
  - `Game.CityOperations.canStart(cityId, CityOperationTypes.BUILD, {ConstructibleType}, false)` → `Success, Plots, ExpandUrbanPlots, InQueue, InProgress, FailureReasons`. `sendRequest` with `X, Y` places.
  - `Game.CityCommands.canStart(…, PURCHASE | CHANGE_GROWTH_MODE | …)`, same shape. Town upgrade: `{Directive: OrderTypes.ORDER_TOWN_UPGRADE}`.
- **Calculated placements:** `calculateAllBuildingsPlacements().buildings[].placements[]` → `{plotID, yieldChanges (by Yields $index), changeDetails[{sourceType, sourcePlotIndex, targetPlotIndex, yieldType, change}]}`. Adjacency *received* by the new building = `sourceType === YieldSourceTypes.ADJACENCY && targetPlotIndex === plotID`.
- **Queue, purchase, Focus, upkeep:** BUILD with `{ConstructibleType, X, Y}` and no `InsertMode` appends to the queue (no known size limit; queue edits use `InsertMode: CityOperationsParametersValues.RemoveAt/Swap/MoveTo`). PURCHASE: `CityCommands` with the same args; `canStart().Cost`, `city.Gold.getBuildingPurchaseCost(YieldTypes.YIELD_GOLD, type)`; gold `Players.Treasury.get(pid).goldBalance`. Focus: `CityCommands CHANGE_GROWTH_MODE {Type: GrowthTypes.PROJECT, ProjectType: hash, City: cityID.id}` (Growing Town = `{Type: GrowthTypes.EXPAND}`). Upkeep: `city.Constructibles.getMaintenance(type)` → positive amounts by `GameInfo.Yields` index.
- **Growth:** a new citizen holds the turn (`NOTIFICATION_NEW_POPULATION`) until placed; the game's place-population mode offers towns only tiles (no specialists). The autopilot tries the advised choice, then every offered tile in order, then a specialist (cities only), and logs `no place for a new citizen …` otherwise. `CityCommands.canStart(cityID, EXPAND, {}, false)` → `Plots[i]` + `ConstructibleTypes[i]` (the improvement the game will build); `city.Growth.isReadyToPlacePopulation`; specialists `city.Workers.GetAllPlacementInfo()` → `{PlotIndex, IsBlocked, NumWorkers, MaxWorkers, CurrentYields, NextYields, CurrentMaintenance, NextMaintenance}` (maintenance = positive costs), assign `PlayerOperations ASSIGN_WORKER {Location, Amount: 1}`.
- **Food:** `town.getSentFoodPerCity()` (one number, per connected city), `city.getConnectedCities()`, `Growth.projectType`, `Growth.turnsUntilGrowth`.
- **Lenses and drawing:** `LensManager` from `/core/ui/lenses/lens-manager.js`: `registerLensLayer(type, {initLayer, applyLayer, removeLayer})`, `registerLens(type, {activeLayers, allowedLayers})`, `setActiveLens`, `getActiveLens`; a lens button via `Controls.decorate("lens-panel", …)` → `panel.createLensButton(caption, lens, group)`. Lines: `WorldUI.createModelGroup(...).addVFXAtPlot("VFX_3dUI_TradeRoute_01", plot, origin, {constants: {start, end, Color3}})`, one per hex, directions E=1 SE=2 SW=3 W=4 NW=5 NE=6 from `GameplayMap.getDirectionToPlot`; the path is ours (`core/xpl-hex.js` `hexLine`). ## Adding things
- **A UI file:** name it `xpl-<name>`, import it from somewhere reachable from `xpl-main.js`, then run `sync-modinfo.py` and `check-imports.mjs`.
- **A string:** both language files; the key prefix is `LOC_XPL_`. `{1_Name}` args, `[icon:YIELD_FOOD]`, `[N]` for a newline in tooltips.
- **A setting:** add it to `DEFAULT_SETTINGS` in `services/xpl-settings.js` and validate it in `sanitize`. Arrays replace on merge. The Buildings checklist stores the *unticked* list (`excluded`) so new buildings start ticked.
- **A tab:** add it to `TABS` in `core/xpl-constants.js`, to the `.html` section, to `xpl-panel.js` registration, and to the `activeTab` whitelist in settings.
