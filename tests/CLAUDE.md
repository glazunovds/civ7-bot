# Tests

Use `npm test`, which runs `node --test "tests/**/*.test.mjs"` (Node ≥ 22; no dependencies). Every test file runs in its own process, so each file may install its own fake engine globals once at the top.

## Two kinds of tests
- **Pure core tests** use `fakes/fake-world.mjs`.
  - `FakeWorld(w, h)` builds a hex grid with a mutable TileFacts table: `set(x, y, kind)`, `patch(x, y, {...})`, `disc(x, y, r, kind)`, `ctx(overrides)` for site scoring.
  - Tile kinds: grass, plains, hill, forest, coast, ocean, mountain, navriver.
  - Used with the real rule book: `buildRuleBook(loadGameInfo("antiquity").info, "AGE_ANTIQUITY", isActivated, { traits, uniqueQuarterTypes })`.
- **End-to-end job tests** use `fakes/fake-engine.mjs` `installFakeEngine(world)`. It installs `GameInfo` (real game data from `fixtures/gameinfo-antiquity.json`) and fakes for:
  - `GameplayMap`, `Players`, `Cities`;
  - `Game.CityOperations` / `CityCommands` (with a log of sent requests), `Game.AgeProgressManager`;
  - `Districts`, `MapConstructibles`, `Constructibles`;
  - `GameTutorial`, `engine` (on/off/trigger), `Locale` (compose returns `KEY(args)`), `Database.makeHash`.

  Then `await import(...)` the module under test *after* installing.
  - **World options:** `tiles(x, y)` (`appeal` is `GameplayMap.getAppeal`), `structures(x, y)`, `cities[{owner,x,y,name,isTown,pop,prod,food,queue,queued,connected,focus,foodSent,grow,readyToGrow,workerCap,resources,resourceCap,factory,factoryResource}]` (`focus` = a Focus ProjectType string or `true`; `queue = {type, turns, pct}` is the item in production, a constructible or a project; `queued` = types behind it, constructibles, projects or units; queue entries carry every type field, -1 where it does not apply, like the game's), `players[{id, civ, uniqueQuarters}]` (`uniqueQuarters` is read on every call, so a test can unlock one mid-turn), `gold`, `buyCost(type)`, `maintenance(city, type)`, `canFocus(id, args)`, `focusProjects(id)`, `expand(id)` (growth tiles), `workers(city)` (specialist placement info), `research {tech|culture: {available, active}, depth: {nodeType: depthUnlocked}}` (available nodes as `GameInfo.ProgressionTreeNodes` hashes; `getNode` answers the hash and depth like the game; made-up ids such as 9011 are not real nodes), `treeRecs(subject)` / `buildRecs(cityId)` (advisor), `readyUnits` (idle units; any unit operation removes one), `units [{id, type, x, y, damage, activity, attacks, moved}]` (the local player's units; `Units.get`, `Units.getPathTo` = a step-by-step straight walk, two tiles a turn, its `plots` are the tiles crossed), `unreachable(x, y, unitId)`, `techs` (researched node types, `Techs.isNodeUnlocked`), `unitCommandResult(id, op, args)` (a full canStart result, e.g. Resettle `Plots`), `rangeTargets(unitId)`, `enemies [{x, y, damage}]` (`MapUnits`), `units[].melee` / `.ranged` (combat strengths), `combat(unitId, {x, y})` → `{dealt, taken}` (answered like the game: `Game.Combat.simulateAttackAsync` returns a token, the event `SimulateCombatResult` follows; an attack fires `Combat`), `districtAt(x, y)` (a settlement's defences there), `villages [{owner, x, y, type}]` (an independent's village: like the game, only among that independent's `Constructibles.getConstructibles()`, never a city; `UNITOPERATION_DISPERSE_INDEPENDENT` succeeds only for a unit standing on one), `indepRelation {id: IndependentRelationship.X}` (default HOSTILE), `districtHealth(x, y)` (of 100; `Players.Districts`), `cities[i].unrest` (`Happiness.hasUnrest`), `turnsFor(city, type)` (`BuildQueue.getTurnsLeft` for an item not in production), `canBuy(type, id, args)` also answers unit purchases (`UnitType`) and `buyCost(type)` prices units too, `victoryPoints {VICTORY_X: {playerId: n}}`, `countdown {VICTORY_X: turns}` (ours) and `countdowns {VICTORY_X: {playerId: turns}}` (anyone's) (`player.Victories`; `Game.VictoryManager` is replaced by a test's own stub), `startsWar(unitId, loc)`, `unitCanStart(id, op, args)`, `unitCommandOk(id, op, args)`, `tradeRoutes`, `tradeCapacity(owner)`, `blocker {type, name}` (what holds the turn), `goldIncome`, `cities[i].happy`, `canBuild(type, cityId, args)`, `canBuy(...)`, `canConvert` (`false`: no town may become a city; or `(cityId) => bool`), `cities[i].cost` (`getTownUpgradeCost`), `placements(city)` (engine placement data), `owningCity(x, y)`, `wonders[]`, `costOf(type)` (also `Production.getProjectProductionCost`), `research.turns {nodeType: turns}` (`getTurnsForNode`), `archive` (great works waiting), `agePoints`, `finalAge` (`AgeProgressManager.isFinalAge`), `ageCountdown` (`ageCountdownStarted`; both may also be assigned on the manager), `claimOk`, `aiSuggestions`, `gameSeed` (`Configuration.getGame().gameSeed`, default 1234), `cities[i].progress {TYPE: pct}` (`BuildQueue.getPercentComplete` of a queued item; the item in production answers `queue.pct`).
  - **Returns:** `{ grid, info, sent }` (`sent` logs every request: kinds operation, command, player, unit, unitCommand, endTurn). The fake also has an in-memory `localStorage`.
  - **DMT:** `installFakeDmt()` simulates Detailed Map Tacks' storage and events. Then `bridge.initDmtBridge(); await new Promise(r => bridge.onDmtReady(r))`.

- **Deals and diplomacy (research/23):** `world.incomingDeals = { [leader]: [items] }` (a deal that leader sent us: `{ type, subType, from, to, amount }`, read with `getWorkingDeal` / `getWorkingDealItem`; `hasPendingDeal` true), `world.dealAnswer(leader)` → the `DealAction` its AI answers our INSPECT with (a `DiplomacyStatement` event; undefined: no answer), `Game.DiplomacySessions.closeSession` logged as a "deal" request. `DiplomacyDealProposalActions` has the game's numbers (PROPOSED 4, ADJUSTED 3, REJECTED 2, INSPECT 7). `DiplomacyProjectStatus` has NO_VIABLE_TARGETS, NOT_UNLOCKED, BLOCKED, ACTIVE; `DiplomacyActionTypes` has an espionage action (`…_ESPIONAGE_STEAL_RICHES`) and a sanction (`…_SABOTAGE_RESEARCH`). `Production.getUnitProductionCost` answers `world.costOf` too. Module state to reset between tests: `steps.resetWar()`, `choices.resetPeace()`, `choices.setDiplomacyScreenProbe(null)`.

Units hurt by ≥ 30 or resting hurt next to hostile soldiers now get out of reach first (`escape`): a test about healing or withdrawing needs no coast nearby, or a ship near it.
- **Commanders (research/25):** a unit whose type ends in `_COMMANDER` is `isCommanderUnit`; `units[].promotions = {can, has, earnable}` gives it `Experience`; `world.unitCommandResult(id, op, args)` answers `UNITCOMMAND_FOCUSED_ATTACK_LAND_RANGED / _MELEE` with `{Plots}`, and sending one fires `Combat` like an attack. The parameter log needs `GameInfo.GlobalParameters` rows (the fixtures have none).
- **Ready units (root CLAUDE.md gotcha 43):** `units[].moves` (moves left, default 2; a unit with `moved: true` and moves left is ready for orders), `units[].dest = {x, y}` (`Units.getQueuedOperationDestination`: a move order it keeps), `world.readyLag` (ms: the ready list moves on that long after a request, like the game). `steps.skipIdleUnits` is async (await it). A test's own fake that marks a skipped unit `moved` must also take its moves (`moves: 0`), as the game does.
- **Final-age military (research/26):** `world.settlementCap` with `world.finalAge` / `world.agePoints` drives `militaryRoom`, and `world.happiness` (the empire's Happiness a turn, `Stats.getNetYield(YIELD_HAPPINESS)`, default 0) its `over` (settlements past the cap, research/30 §1); Operation Ivy needs the Modern fixture (`installFakeEngine(world, "modern")`, as in `autopilot-military.test.mjs`), its city by `world.canBuild` and `world.costOf`. Natural wonders in site tests: `FakeWorld.patch(x, y, {isNaturalWonder: true, feature})` and `ctx({naturalWonders: true})`.
- **Weights (root gotcha 45):** a test that wants other weights passes `{ ...DEFAULT_SETTINGS, yieldBias: {…} }` (a single `{F, P, …}` set is used as it is; per-focus sets need `biasFocus`, and DEFAULT_SETTINGS has science's F 0.7, S 1.5 under `SCIENCE`) (or `profile`); production code never calls `getProfile(settings.profile)` (use `profileFor`). `cities[i].food` is the city's net food (the growth advice's scarcity of gains).
- **Plague (root gotcha 46):** `world.plotEffects(x, y)` → `["PLOTEFFECT_PLAGUE", …]` (`MapPlotEffects.getPlotEffects`; the fake adds the game's damaging `PlotEffects` rows, the fixtures have none), `cities[i].infected` (`city.isInfected`). Unit training costs come from `world.costOf` (`Production.getUnitProductionCost`): a test that wants a soldier trained keeps it within 10 turns of the city's `prod`.
- **Prove on a copy:** the repo's `mod/` is linked into the game, which reloads every edit (and once refused a write while it held the file). Revert-and-test provers copy `mod/`, `tests/` and `package.json` to a scratch folder first.
- **Like the game (research/22):** there is no global `ComponentID` (the game's UI imports it; compare ids with `core/xpl-component-id.js`), and a town conversion answers `Success` only when `world.gold` covers its cost, else `InsufficientFunds: true` (the game's own button is disabled then). Two bugs hid behind fakes that answered otherwise.

Triumphs are a test's own `GameInfo.Legacies` rows (`FirstPlayerOnly` for a race) and `Players.get(0).Legacies` (`isValidLegacy`, `getProgress`, `isTriggered`: legacy-milestones.test.mjs `withTriumphs`); legacy paths are read nowhere (games 42-43).

## Rules
- **Fakes must behave like the game, not like our assumptions.** Two bugs hid behind fakes that were too kind: the fake said navigable rivers were water, and the fixture's `Terrains` has no `Mountain` column, exactly like the game. When the real game behaves differently from a fake, fix the fake first.
- **Prove every new regression test.** Temporarily revert the fix and watch the test fail, then restore it. Several tests here first passed without their fix, for example because the city owned every tile so no "future tile" case existed.
- **`GameInfo` tables behave like the game's:** `lookup`, `length`, `filter`, `find`, `findIndex`, `forEach`, `for…of`; any other array method throws (as in game). Test code that needs `.map` on a table uses `Array.from(GameInfo.X, fn)`.
- **Hex geometry is "odd-r".** Pick neighbours with `grid.neighbours(idx)` or `grid.radius(idx, r)` instead of hand-written coordinates.
- **A fake city owns only its centre and the ring around it** (`getPurchasedPlots`: radius 1). A test that needs tiles counted for a city (urban tiles, buildings) must put them there: a test of the 75-yield mark first passed for the wrong reason because its tiles lay 2 away.
- **Fixture tables** also include `ProgressionTreeNodes`, `ProgressionTreeNodeUnlocks`, `ProgressionTreePrereqs`, `GreatWorks`, `Victories`, `VictoryTypes`, `Attributes`, `ConstructibleModifiers` (Innovation wonders: `*_SCIENCE_VP`) and `Unit_Stats` (combat strengths: `lookup(UnitType)`, as the game's UI reads them) (the extractor writes tables in sorted order, so a re-extract gives the same file).
- **Fixture coverage:** Antiquity (`gameinfo-antiquity.json`, used by the fake engine) and Modern (`gameinfo-modern.json`, load it with `loadGameInfo("modern")` for pure rule-book tests, e.g. the Airfield). For Exploration logic extract it: `python -I tools/extract-fixtures.py exploration`. The extractor reads base-standard plus that age's data only.
- **Time-aware plans:** tests that don't care about build order should pass `timeAware: false` (it is on by default) to keep expectations simple.
- **Same-turn cache and fast recalculation.** The planner caches the game's per-city answers for the turn and re-solves only changed settlements. A test that edits the fake world between two plans in the same turn must call `clearEngineCache()` (`ui/data/xpl-engine-cache.js`) or `engine.trigger(...)` the event the game would fire; to force a full plan pass `buildings.incremental: false`.
- **Speed:** `node tools/bench-plan.mjs` plans every building for 8 fake cities and prints CPU per phase and the work counters (gains, tile values, views).
- **Random cities (research/27):** `fakes/random-city.mjs`, used by `placement-anneal.test.mjs` and `tools/bench-optimality.mjs`:
  - `makeRandomCity(seed)`: a Palace at (10,8), resources, mountains, hills, coast, a river, maybe a wonder or a natural wonder;
  - `randomCityState(map, book, {profile, horizon, settlement})`: owns ring 1, plans to ring 3;
  - `planValue(state)`: every planned building re-placed from an empty plan, so the exact deltas add up to the plan's value;
  - `placeAll`, `layoutOf`.
- **Older solver behaviour in tests:** pass `{ annealSteps: 0 }` to `solveLayout`. PlanState tests without `specialists` keep the flat `adjMult`, and `nextAge` defaults to 0.
- **Wonders (research/27 §6–7):**
  - `world.wonders` is read on every call (a test may add a built wonder mid-file).
  - Wonder anchors in a job test need tiles the city may plan: the fake city owns only ring 1, and tiles owned by us but not that city are left out of the plan's area.
  - `world.canBuild` answers `Plots` for an available wonder.
  - The fixtures now include `Constructible_ValidBiomes` and `CivilizationFavoredWonders` (Greece: the Oracle).
  - Lost races: an omniscient wonder planner (`wonders: {omniscient: true}`) reads a rival city's `queue {type, turns}`; `steps.cashOutLostWonders()` reads `state.results.wonders`, so run `runWonderPlanner(settings)` first. The refund guard and the wonder step read it too: refresh it after changing a rival's queue.
  - Wonder orders (research/28 §1): an order of this turn counts as started until the queue shows it, and the fake's queue never changes on a request, so a file whose tests each order wonders resets them: `beforeEach(() => steps.resetWonderOrders())`. A later turn: assign `Game.turn`.
  - Queue passes (root gotcha 54): `steps.beginQueuePass()` / `endQueuePass()` hold each city's queue to one edit; the hud opens one per pass, a test opens its own (none open: no limit).
  - Notices: `world.notifications[i].summary` is what `Game.Notifications.getSummary` answers.
- **Traits (research/28 §4):** a civilization ability for a test: set `Players.get(0).civilizationType` to a fixture civilization's hash and replace `GameInfo.CivilizationTraits`, `TraitModifiers`, `Modifiers`, `DynamicModifiers` and `ModifierArguments` (restore them after); `traitEffects()` is cached on those tables.
- **Age changes (research/29 §4):** `GameTutorial._props.clear()` is an age change (the save's properties are gone); the settings' memory survives it (`settings.remember` / `recall(gameKey(), …)`; `gameKey()` is `1234|` with the fake's seed and no leader).
- **Games 24–26 (research/31):**
  - **No end on the clock:** the fake's `AgeProgressManager.isExtendedGame` reads `world.extendedGame`, and `getMaxAgeProgressionPoints()` reads `world.ageMax` (default 100; 0 means no age timer). The score victory is a test's own stub: `Game.VictoryManager = { isScoreVictoryEnabled: () => false }`; without one it counts as on.
  - **Syncretism:** the fake has `SyncreticChoiceTypes` and `PlayerOperationTypes.CHOOSE_SYNCRETISM_*`; a test stubs `Game.Unlocks` and `Players.get(0).Identity`.
  - **Production first:** reads `world.placements(city)` with production in `yieldChanges[GameInfo.Yields.lookup("YIELD_PRODUCTION").$index]`, so reset it between tests with `steps.resetProductionFirst()`.
  - **The queue probe:** fire `engine.trigger("CityMadePurchase", {cityID})` for a purchase.
  - **Building prices:** the fake prices any building at 250 gold unless `world.buyCost` says otherwise, which `buildRatherThanBuy` compares with the income.
- **Game 27 (research/31 §8):**
  - **Other net yields:** `cities[i].nets = { YIELD_SCIENCE: 40, … }` sets a city's other net yields (`city.Yields.getNetYield`), for the penalty below zero Happiness. Without it they are 1; production is `prod`, food `food`, happiness `happy`.
  - **Ranged attacks:** `UNITOPERATION_RANGE_ATTACK` with `X` fires `Combat`, like a melee attack.
  - **Units on guard:** use `activity: UnitActivityTypes.SLEEP`; the fake has no FORTIFY or ALERT activity.
  - **Strikes:** `strikeRaiders` now shoots with ranged units. A test that expects no orders from it gives its ranged units no `rangeTargets`, or no war.
- **Game 27's review (research/32):**
  - **Queue passes:** the levers test's `passes(n, city, id)` runs `pushVictoryWork` in `n` queue passes and applies each pass's MoveTo to the fake's `queue`/`queued` (`applyMoves`). The fake's own queue never changes on a request.
  - **Purchase tests and wonders:** no building is bought in a city whose queue holds a wonder, or where one was ordered this turn (`holdsWonder`). A purchase test keeps wonders out of that city's `queued`; a test that orders a wonder and then buys moves `Game.turn` on to buy there.
- **The review after game 27 (research/33):**
  - **The science race:** `world.victoryPoints = { VICTORY_SCIENCE_MODERN: { 0: 95 } }` is our Innovation (`innovationNeed`), and `world.countdowns = { VICTORY_SCIENCE_MODERN: { 1: 3 } }` a rival's countdown, 3 of its 5 turns gone (`ageOutlook` then counts 2). Without them the need is 100.
  - **Tiles from the plan:** with `state.results.plans` set, the victory work and the advisor's buildings take the plan's tile for that building, else a tile the plan leaves free. A test that checks a tile either sets no plan or sets the plan it means.
  - **Production first** (the levers test's `withIronworks`): its work is now the projects the city runs before the goal or the age's end, so a test's expected work depends on the age's turns left (96 in the levers test) and the Innovation needed.
  - **Placement model:** `isConnected` is timed (`urbanTime`). A test that places buildings with their own `eta` must place a connector no later than the building behind it.
- **Game 28 (research/34, research/35):**
  - **Project costs like the game:** `Production.getProjectProductionCost` falls back to the project's own `Cost` (Preparation 2000, Launch Satellite 1000, the Radio Telescope 1200), not 100. A test of weak cities prices its projects with `world.costOf`.
  - **The race decides sites:** beyond the victory's own pad a site is placed or bought only where it brings the goal sooner (`siteHelps`). Preparation comes in steps of 15, so a test that wants an Airfield sets the need where a flight's 5 matter (`world.victoryPoints`).
  - **Happiness:** `cities[i].happy` with `nets` drives the penalty everywhere now: the cards (`world.workers` gives specialists and their `CurrentMaintenance`, `world.maintenance` building upkeep on tiles from `world.structures`), production first and the building plan (`recovery`).
  - **Military buildings:** the Barracks and the Military Academy are production buildings (TypeTag PRODUCTION): no longer skipped in peace.
  - **The building-job test** keeps its `world` in a variable (`worldCity()`) to set a city's Happiness.
- **Game 29 (research/36):**
  - **Other players' units:** `Players.get(id).Units.getUnits()` answers that player's `world.enemies` (by `owner`), as `Units.get` does (`hostileAircraftNear`).
  - **Command radius:** `world.commandRadius(unitId)` → plot indices (`Units.getCommandRadiusPlots`; default none: 1 + Merit).
  - **Lone raiders:** a land raider 3–4 tiles from a settlement with no melee guard of ours as strong within 2 now threatens it (`strong`). A test that wants a lone raider 3+ tiles away ignored gives that settlement a guard.
  - **Guard goals:** a unit sent to guard counts as on its way while its activity is OPERATION (or on the turn it was sent), its `dest` near the settlement; set `activity: UnitActivityTypes.OPERATION` and move `Game.turn` to test a later turn. Healing, asleep or idle elsewhere on a later turn: it no longer counts.
  - **Module state:** `steps.resetWar()` also forgets the war fronts, the defenders bought this turn (they count when training is decided) and those queued per settlement; the defence test's `reset()` calls it. `units.resetUnitGoals()` forgets the units the autopilot fortified (`restedByUs`).
  - **Training distances:** a defender's walk counts (its BaseMoves a turn, `DEFENDER_ARRIVAL_TURNS` 16), so a test that wants one trained keeps the city's training plus the walk within that.
- **Research/37 Phase 1:**
  - **Armies:** `units[i].onMap: false` (packed: `isOnMap` false, not on `MapUnits` plots), `units[i].army` / `enemies[i].army` (a number: the `armyId`), `world.armies = { "<owner>:<army>": { x, y, capacity, unitCount } }` (`Armies.get`), `units[i].embarked` (`isEmbarked`; left out, the code reads the tile). Enemies take `onMap` and commander types too.
  - **The centres' unit** is in the settings' game memory, so it outlives a test: a file's `reset()` clears it with `settings.remember(gameKey(), { melee: null })`; `centres.noteMeleeObtained(GameInfo.Units.lookup(type), "trained")` gives one. A training: `engine.trigger("CityProductionCompleted", { cityID, productionKind: ProductionKind.UNIT, productionItem: hash })`.
  - **QUEUED_MELEE** is wanted at an age's start whatever units the test gives: a test that expects no unit trained notes one obtained (`autopilot-war.test.mjs`), and `canBuild` keeps the best trainable melee unit realistic (the fake allows every civilization's units by default).
  - **Fighters** need an Airfield base: an `UNIT_AERODROME_COMMANDER` of ours with an `army`, its `world.armies` entry and `world.owningCity` naming its city (`autopilot-air.test.mjs`).
  - **Upgrades:** the fixtures have no `UnitUpgrades`; a test stubs `GameInfo.UnitUpgrades = { find }` and allows `UNITCOMMAND_UPGRADE` with `unitCommandOk`.
- **Research/37 Phase 2:**
  - **Turn 1 is an age's start:** the fake's `Game.turn` starts at 1, where soldiers already resting count as the autopilot's own (the age change brought them back fortified). A test about the player's own fortified units sets `Game.turn` above 2 (`autopilot-fronts.test.mjs`).
